Item by item

Each bullet from the guide, with what was done and how, or why not.

01 JavaScript-dependent content

  • Done Serve all main content in the initial HTML. The build opens each page in a headless browser and saves the rendered page as its own HTML file, 20 in all. Tested with JavaScript switched off: the pages read in full.
  • Done Title, meta description, canonical, H1, body copy, images and internal links in the raw HTML. All present on every page; checked by script on every page on 8 October.
  • Done Internal links as standard anchors. They already were; confirmed.
  • Done JavaScript enhances but is not required. The sliders and animations still run; the content does not depend on them.
  • Staging The staging preview currently builds the site its own way and does not include the pre-render step, so view-source there still shows the bare page. The live site will be served from the pre-rendered pages, and we will confirm view-source on the live domain at launch.

Note: the staging site still carries a noindex tag and blocks crawlers, on purpose, so the staging copy never competes with the live domain. The live build removes both.

02 Clickable business address

  • Done Footer address links to the Google Business Profile listing in a new tab. Also on the contact page. Verified in a browser that the link opens "SprayIT Solutions (VIC) Pty Ltd".
  • Done Address text matches the listing exactly: "Factory 4/114 Colemans Rd, Carrum Downs VIC 3201".
  • Done Phone as a tel: link, email as a mailto: link. The phone number on the site is the one on the Google listing, 1300 177 729, so the name, address and phone agree across the site and the listing.

03 USP section

  • Done Moved directly below the home page hero.
  • Done HTML text with icons, alt text on logos. It was already built as text; client logos already carried alt text.
  • Done On mobile, wraps two across; never hidden.
  • Done Reused on Residential and on the Underfloor, Roof & Ceiling and Wall pages. Not repeated on Commercial, whose opening section already shows the same figures; the same numbers twice on one page reads as padding.

04 Navigation, services and sub-services

  • Done Services menu in the main navigation, listing Spray Foam, Residential (Underfloor, Roof & Ceiling, Walls & Retrofit) and Commercial (Factory & Warehouse, Farming, Mining). Main service names are links.
  • Done All menu links are in the raw HTML; the menu is hidden with CSS when closed, never injected.
  • Done Desktop opens on hover and click, works with Tab, Enter and Escape. Mobile is an accordion inside the menu drawer.
  • Note The residential sub-services link to their own pages. The commercial ones land on the matching section of the Commercial page; see the question below about separate pages for them.

05 Before and after gallery

  • Done Category filters by service. A "Surface" filter row (Roof & ceiling, Walls, Underfloor, Specialty work) alongside Residential / Commercial. Counts update as filters combine.
  • Partly Each project as a before/after pair. One pair exists (the subfloor job) and it is in as a slider. The other jobs have no "before" photograph. Needs photographs from the client.
  • Done WebP, width and height set, lazy loading below the fold.
  • Done Descriptive alt text on every image.
  • Done Optional: matching category on each service page. Each of the three service pages shows photographs of matching jobs from the gallery, with a link to the full gallery.

06 FAQs on dedicated pages

  • Done Residential carries your ten FAQs from the outline. Underfloor, Roof & Ceiling and Wall carry six each, Commercial six and Spray Foam five, each written for its page; nothing is shared between pages.
  • Done Accordion with every answer in the HTML, hidden with CSS, never fetched on click.
  • Done "FAQs about [service]" as the H2 (Residential uses your heading, "Spray Foam FAQs"), each question an H3 containing a button. FAQPage structured data built from the same text the visitor sees.
  • Partly On sub-service pages. Done for the three residential sub-service pages. The commercial sectors (Factory & Warehouse, Farming, Mining) are sections of the Commercial page rather than pages of their own; see the question below.

  • Partly Author box at the end of every post with name, role and bio. Photo and credentials are waiting on the client; initials show until the photo arrives.
  • Done Byline at the top with the published date. A last-updated date appears once an article is edited.
  • Done One author profile used everywhere.

  • Not done Team section. Needs a photo, name, role and one line for each person. Requested from the client.
  • Not done Company journey timeline. Needs the milestones (founded, first rig, biggest jobs, certifications). Requested from the client.
  • Not done Neither will be built with placeholder people or invented dates. The layout is quick once the facts arrive.

09 Contact Us: Google Map

  • Done Map embedded beside the address, phone, email and form. Lazy-loaded, titled, responsive.
  • Done Pinned to the listing. The embed looks the business up by name and address and shows the listing's pin. If you would rather it used the Business Profile's own embed link (Share, then Embed a map), send the link and it goes straight in.
  • Done "How did you hear about us?" as a required dropdown. Five options rather than three: Google search, Google ad, Referral from a friend, builder or tradie, Facebook / Instagram / LinkedIn, Somewhere else. Customers do not recognise "Google Organic", and a required field with only three options forces wrong answers. The answer is sent to the CRM with every enquiry, alongside the automatic campaign and referrer capture the site already does.

10 Typography

  • Done Heading sizes reduced to the recommended scale. Measured on the site: desktop H1 56px, H2 40px, H3 24px, FAQ questions 20px, labels 13px; phone H1 32px, H2 26px, FAQ questions 16px. Line heights 1.1, 1.15 and 1.25.
  • Done Collapsed word spacing fixed. Tracking capped at -0.02em on every heading size and word spacing opened, so "What is R-Value?" reads as three words.
  • Done Scale defined as CSS variables, with fluid clamp() sizing.
  • Done One H1 per page, heading levels in order. Checked by script on every page on 8 October.
  • Not done H1 and H2 at Bold weight. The display face is set at semibold across the site. Bold would change the brand look for a difference few readers would notice, and would add another font file. Easy to change if it matters to you.

11 FAQ accordion design

  • Done Question size 18 to 20px desktop, 16 to 17px mobile.
  • Done Whole row clickable; 44px target on the icon.
  • Done Each question is a button with aria-expanded, controlling a labelled panel.
  • Done First question open by default; others open without the page jumping.
  • Done Side card: "Call 1300 177 729" as a tel: button (the Google listing number), plus a "Get a Free Quote" link.
  • Done Diagonal background stripes replaced with a plain backdrop.

12 Scrolling ticker and auto-play carousel

  • Done Ticker reduced from 28 to 52px down to 20 to 24px, and slowed.
  • Done Ticker pauses on hover and keyboard focus; no motion at all under prefers-reduced-motion.
  • Done Carousel pause button kept; slide dots are 44px tap targets with a visible active state.
  • Done Carousels hold each slide for 6 seconds and stop auto-playing once a visitor picks a slide or swipes. The new home photo rotation follows the same rules, and does not move at all under reduced motion.
  • Done Stats labels at 14px, colour checked for contrast.

13 Colour contrast and readability

  • Done Body text at 4.5:1 or better. On 8 October every visible text element on all 14 public pages was measured against its background. One small green label measured 3.4:1 and was darkened; everything else passed.
  • Done Large headings and icons at 3:1 or better, including the green words: 3.7:1 on white, 3.2:1 on the tinted band.
  • Done Body text line length capped at 62 characters.
  • Done No text over busy images without an overlay; photo captions sit on a dark gradient, and the numbers on photographs sit on a solid chip.

14 Mobile experience and calls to action

  • Done Sticky bottom bar on phones with Call and Get a Free Quote. Hidden on the contact and booking pages, where it would point at the page you are on.
  • Done One primary label everywhere: "Get a Free Quote" (replaced a mix of "Request a Free Quote" and "Get a Free Quote").
  • Done CTA in the hero, a short one mid-page after the proof, and the closing band at the end of each service page.
  • Done Tested at 375, 390 and 414px on all 14 public pages on 8 October: no horizontal scroll, nothing cut off.
  • Done Breadcrumbs on every page, with BreadcrumbList structured data; the service pages sit under Residential in the trail.

15 Buttons and forms

  • Done One primary and one secondary style, minimum height 44px everywhere.
  • Done Hover, keyboard focus and active states on every link and button.
  • Done Visible labels, required fields marked both in the note ("Everything is required unless it says optional") and in the markup for screen readers, minimal fields, correct mobile keyboards for phone, email and postcode.
  • Done Inline error messages and a thank-you page after submitting. Already in place.
  • Done Consistent spacing system. Already in place.

16 Page speed, Core Web Vitals

  • Done Images as WebP, correctly sized, width and height set on every image, lazy-loaded below the fold.
  • Done Preload the hero image. The home hero is now a photograph; it is preloaded at high priority, and phones get a version half the size.
  • Done Fonts self-hosted: two families, four weights (down from seven loaded from a third-party CDN), font-display: swap, the first-paint pair preloaded.
  • Done Non-critical scripts deferred. Analytics loads asynchronously and only when an ID is configured. There is no chat widget on the site yet; when it is added it will load the same way.
  • To measure LCP under 2.5s, CLS under 0.1, INP under 200ms. These need the live host and real visitors; a local preview gives meaningless numbers. We will check them in Search Console after launch.
